## 見つけた問題と直したこと

1. **NeMo の環境が入らない**（`google.protobuf` のバージョンエラー）
   - 原因: Colab には `google_generativeai-*-nspkg.pth` があって、Python の起動時に `google` パッケージをシステム側のパスだけで作ってしまいます。そのせいで venv に入れた新しい protobuf（7.x）ではなく、システムの古い protobuf（5.29）が読まれて、onnx（gencode 6.31）で落ちていました。
   - 修正: `runtime._fix_google_namespace()` を追加しました。システムの site-packages を見る venv に `.pth` を置いて、venv 側の `google/` を先に登録します（システム側の `google.colab` などもそのまま読めます）。再現テスト `v3/tests/test_runtime.py` も足しました。
2. **vLLM サーバーが起動しない**（Qwen・Cohere の両方）
   - 原因: vLLM 0.30 の FlashInfer サンプラーが初回に JIT ビルドしようとして、`ninja` が PATH にない（venv の bin にはある）ため失敗していました。PATH を通しても、Colab の nvcc 12.8 と vLLM の torch（cu132）が合わないのでビルドは危なっかしいです。
   - 修正: vLLM サーバーを起動するときに venv の `bin` を PATH の先頭に入れ、`VLLM_USE_FLASHINFER_SAMPLER=0`（PyTorch 版のサンプラー）にしました。これで両方とも起動して動きました。
3. **kotoba-whisper でワーカーが segfault**
   - 原因: faster-whisper の単語タイムスタンプ（`find_alignment`）の中で落ちていました。蒸留モデル（デコーダ 2 層）に、large-v3 用の alignment heads が当たっているためと考えられます。
   - 修正: `FasterWhisperEngine` に `word_timestamps`（既定は `auto`。モデル名に kotoba / distil が入っていれば切る）を足しました。kotoba のプリセットは `native_ts=False` にして、タイムスタンプは Qwen3-ForcedAligner で付けるようにしました。カスタムで distil 系を指定したときも同じ扱いです。
4. **⑥ の VRAM 峰が前のモデルの値のまま**
   - 修正: ワーカーで、モデルを読み込むときと文字起こしを始めるときに `torch.cuda.reset_peak_memory_stats()` するようにしました（torch をまだ読んでいないワーカーでは何もしません）。
5. **環境のインストールに失敗したときに、肝心の import エラーが見えない**
   - 修正: 表示の順番を「インストールログの末尾 → 確認（import）のエラー」にして、最後にエラーが見えるようにしました。
6. **テスト用スクリプトの CER が水増しされていた**（`v3/tools/colab_e2e.py`）
   - ⑥ は先頭 300 秒だけなのに、6 分ぶんの正解文と比べていました。発話ごとの時刻を `meeting_cv8.utts.json` に保存して、比較区間ぶんの正解文（`meeting_cv8.ref_0-300.txt`）を作るようにしました。
7. **Colab CLI まわり**（`v3/COLAB_TEST.md` に追記）
   - google-colab-cli 0.7.2 は `jupyter-kernel-client==0.8` 固定ですが、0.8 には `JupyterSubprotocol` がなく `exec` が落ちます。0.9.0 に上書きして入れる手順にしました。
   - `colab exec` の `--timeout` は既定で 30 秒です（切れても VM 側は動き続けます）。
   - 通しテストでカーネルがふさがっていても、`colab ssh --proxy-mode` で SSH すればログや venv を並行して調べられます。

8. **Cohere の規約**: 最初はこの HF アカウントが未同意で 403 でした。テストの途中でリポジトリの持ち主が同意してくれて、ふつう版も vLLM 版も動きました（pyannote は最初から OK。トークンの権限は問題なし）。

ローカルでは `pytest v3/tests` が 35 件すべて通ることを確かめ、`build_notebook.py` でノートブックを作り直しました。

## 追加の対応（テストのあと）

### kotoba-whisper / Cohere の区切り方

1つのクリップに、無音をはさんで何人ぶんもの発話が入っていると、そのうちいくつか（とくにクリップの最後や、無音のあとの発話）をまるごと飛ばしていました。
プリセットに `max_clip`（クリップの長さの上限）と `max_gap`（この秒数より長い無音で別のクリップにする）を足して、この2つのモデルだけ短く区切るようにしました。

Colab のログイン情報が無効になっていたので、このクラウド環境の CPU（kotoba は int8、Cohere は fp32）で本物のパイプラインを動かしてくらべました（同じ CV8 の先頭 300 秒。正解 1,052 字）。

| モデル | max_clip | max_gap | CER | 文字数 |
|---|---|---|---|---|
| kotoba-whisper v2.0 | 30 秒 | 6 秒（もと） | 24.4% | 920 |
| | 20 秒 | 6 秒 | 12.7% | 998 |
| | 15 秒 | 6 秒 | 23.2% | 873 |
| | 10 秒 | 6 秒 | 11.6% | 1,030 |
| | 30 秒 | **1 秒** | **8.3%** | 1,043 |
| | **15 秒** | **1 秒** | **8.3%** | 1,043 |
| | 30 秒 | 0.5 秒 | 8.3% | 1,043 |
| Cohere Transcribe 2B | 30 秒 | 6 秒（もと） | 19.4% | 924 |
| | 10 秒 | 6 秒 | 10.6% | 1,024 |
| | 30 秒 | **1 秒** | **4.3%** | 1,052 |
| | **15 秒** | **1 秒** | **4.3%** | 1,052 |

長さだけ短くしても、でこぼこしてあまり安定しません。効いたのは「無音で区切る」ほうでした。
本物の会議では、話者の交代が 1 秒より短い間でつながることもあるので、念のため長さの上限（15 秒）もいっしょにかけて、**15 秒・無音 1 秒**にしました（Cohere の vLLM 版も同じ）。
Cohere は Qwen3-ASR 1.7B（8.8%）よりよい値になっています。ただし CPU で測った値なので、GPU（bf16）ではまた少し変わるかもしれません。
